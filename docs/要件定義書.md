## 1. 概要

- **ジャンル**：肩越し視点（TPS）のサバイバルホラー。『バイオハザード4』へのオマージュ。
- **動作環境**：ブラウザだけで動く。ビルド不要の静的ファイル（`index.html` + `game.js` + 同梱の three.js）。
- **見た目**：初代プレイステーション風（320×240相当の低解像度、頂点の揺れ、15bitカラー＋ディザ）。
- **参考**：ユーザーの別作品 DOOM風ゲーム（`ryodai426/DOOM`、単一HTMLのレイキャスター、https://doom-ryodai426.vercel.app/）。
- **公開**：Vercel を想定（Framework Preset「Other」、ビルドなし、`main` を本番にする）。デプロイ作業はユーザー自身が行う（この開発環境からは Vercel API に接続できない）。

### オリジナリティに関する方針（重要）
- 本家作品の固有名詞・キャラクター・セリフは使わない。主人公「レイ・カーヴァー」、商人のセリフ、敵の名前（処刑人・変異体）などはすべてオリジナル。
- 「ラクーンシティ風」は雰囲気だけ寄せたオリジナルの街。R.P.D.などの固有名は使わず、看板は「POLICE」だけ。

## 3. 画面・表示の仕様

### 3.1 グラフィック（PS1風・唯一のモード）
- シーンを低解像度のレンダーターゲットに描き、ニアレストで拡大する。
  - PC：320×240 固定。
  - スマホ：短い辺が240ドット（縦持ち 240×427、横持ち 427×240）。
- 後処理：トーンマップ → sRGB → 15bitカラー（各色32段階）＋4×4ベイヤーディザ。
- 頂点スナップ：`THREE.ShaderChunk.project_vertex` を書き換え、クリップ空間で160×120の格子に吸着させる。
  - 影の深度パス（`DEPTH_PACKING`）と、カメラ後方の頂点（`w <= 0.1`）には適用しない。
  - **大きな床は約8m四方に分割すること**（1枚の巨大ポリゴンだと吸着で表示が崩れる。過去に地面がちらつく不具合の原因になった）。
- テクスチャはニアレスト補間・異方性なし。霧はPS1風に濃いめ（各雰囲気の密度×1.35）。
- 高画質モードはユーザーの指示で**削除済み**。復活させない。

### 3.1.1 キャラクターの見やすさ補正
- 主人公・敵・商人が暗い背景に沈んで見えにくいという指摘を受けて、**キャラクターだけ**に軽い補正をかけている（背景の明るさは変えていない）。
  - 自分の色でほんのり光る（`charLift`：色の約10%）。
  - 輪郭光（リムライト）：視線に対して横を向いた面ほど明るくなる。色は空の光（`hs`）の色、強さ0.2。
  - 霧のかかり方を72%に弱める（遠くの敵が霧に溶けにくい）。
- 実装：`charMat()` / `charify()` が `MeshStandardMaterial` を複製し、`onBeforeCompile` でシェーダーに処理を足す。強さは `applyAtmos()` で雰囲気ごとに更新する。
- 雰囲気ごとの倍率は `ATMOS` の `vis`（省略時は1）。**停電（`indoorDark`）は0.45**にして、ライトで照らす怖さを残している。
- 新しくキャラクターを作るときは `charify(root)` を呼ぶこと（`makeVillager`、主人公、商人で呼んでいる）。強くしすぎると発光しているように見えて不自然になる。

### 3.2 画面比率とブラウン管の枠
- **PC**：4:3の画面を、ブラウン管テレビの枠の中に表示する。横長ディスプレイでは左右に黒帯が入る。
- **スマホ**：縦持ち 9:16、横持ち 16:9 の固定比率で、同じく枠の中に表示する（枠はPCより細め）。
  - **黒帯には何も表示しない**。操作ボタン・HUD・メニューはすべてゲーム画面（`#screen`）の中に置く。
- 枠は暗いプラスチック調で、右下に赤い電源ランプ、角丸、周辺が暗く沈むガラス面。
- **画面そのものにブラウン管表現（走査線など）は入れない**。PS1風の見た目だけにする。
- サイズ計算は `game.js` の `fit()`。CSS変数 `--k`（HUDの拡大率）と `--bez`（枠の太さ）を設定する。

### 3.3 文字
- HUD・メニューはドットフォント「DotGothic16」。細くて読みにくいという指摘があったため、ふち（`-webkit-text-stroke`）と黒い影で太く見せ、文字サイズも大きめにしている。
- タイトルロゴは Cinzel（セリフ体）。

### 3.3.1 レーダー
- 画面の**左下**に円形のレーダー。自分が中心、画面の向いている方向が上（視点に合わせて回る）。
  - PC：左下の隅（ログはその上に移動）。スマホ縦：「ケース」ボタンの上。スマホ横：左スティックの右隣。
- 表示するのは「**視認した敵**」：20m以内で、目の高さから敵の首までの間に壁がない敵（前後左右どこでも）。見えなくなってから1.2秒で消える。
- 通常の敵は赤い四角、ボスは大きめのオレンジ。視界の範囲を薄い扇形、10mを内側の円で示す。
- 実装：`updateRadar()`（`updateHUD()` から呼ぶ）。見通しの判定は0.1秒ごと（`segClear()`）。定数 `RADAR_R`、`RADAR_MEM`。
- 右下はボタンやHUDが集中しているので、ユーザーの指示で左下に置いている。

### 3.4 タイトル画面
- ゲーム名「**PANDEMIC ZERO**」（PANDEMICは白、ZEROは赤）。小見出し「パンデミック・ゼロ」。
- 背景は専用の3Dシーン（`titleScene`）。
  - 血のこすれ跡・手形・弾痕・ひび・欠けのある崩れたコンクリート壁。
  - 立っているドラム缶と倒れたドラム缶、破片。
  - 上から照らす警察署の蛍光灯。
- 照明は不規則に点滅するが、**警察署ステージより控えめ**（見やすさ優先）。普段はほぼ一定で、2.5〜6.5秒ごとに短く暗くなる。タイトル文字も連動して明滅する（CSS変数 `--flick`）。
- 文字やカードは上下に寄せ、照らされた壁が中央に見える配置にしている。

### 4.1 ガード（蹴りは削除済み）
- **1回押すと約0.5秒だけガードする**。長押ししても延長されない。終了後に0.35秒のクールダウンがある（ナイフと同じ「1回押して1回」の操作感）。
- **ジャストガード**（押してから0.2秒以内に受ける）：ダメージ1割、相手が大きくのけぞる（`staggerKind = 'recoil'`）。
- **通常ガード**（それ以降）：ダメージ35%、相手が軽くのけぞる。
- **掴み**：ガード中なら無効化し、相手をのけぞらせる。
- **方向**：正面からの攻撃にのみ有効。後ろや真横からは防げない。投げ斧は防げる。爆発は防げない。
- **ボス**：ジャストガードで隙ができ、ひざをつくまでの値（stagger）が溜まる。
- **ガード中の制限**：移動は秒速約1.1mに落ちる。射撃・リロードはできない。
- 敵が攻撃や掴みの予備動作に入ると「F ガード！」のヒントを表示する。
- 定数：`GUARD_T`、`GUARD_JUST`、`GUARD_CD`。判定は `hurtPlayer()` と `guardFacing()`。`hurtPlayer()` は false（無効）、`'guard'`（防御）、true（被弾）を返す。

## 5. ゲーム内容

### 5.0 物語とステージの大枠（ユーザー指定・2026-10-31）
**進め方**：まずTEST版で各ステージを作って動作を確認し、そのあとでストーリーを組み立てる（会話・演出・ステージ間のつながりは次の段階）。

| # | ステージ | 物語上の役割 |
| --- | --- | --- |
| 1 | 村（作成済み） | ここからパンデミックが始まる。調査隊が失踪し、主人公が探索することになる。 |
| 2 | 町＋警察署 | 村から町へ戻ると、すでにウイルスはばらまかれた後。攻撃を耐えきったら警察署に入り、原因を突き止める。 |
| 3 | 下水道＋地下鉄 | 原因を突き止めた主人公は、警察署から下水道に降り、地下鉄を伝って地下を探索する。（詳細は下の「STAGE 3」） |
| 4 | 地下研究所 | 地下鉄の車両倉庫から秘密の入り口を通って地下研究所へ。ここがパンデミックの発生源で、ラスボスと対峙する。 |

### 5.1 ステージ（タイトルで選択）
各ステージは `STAGES` テーブルで定義する。ビルダー関数、章（waves）、出現地点、開始位置、商人の位置、ボスを持つ。ステージを切り替えるときは `buildStage(id)` でワールドを作り直す。

| ID | タイトルの表示 | 内容 |
| --- | --- | --- |
| `village` | STAGE 1 赤霧の村 | 霧の山村。寄生された村人（フォーク・鎌・斧投げ・松明・巨漢）。第3章以降は頭を飛ばすと寄生体が出る。ボス「処刑人」（教会から出てくる） |
| `city` → `stationIn` | STAGE 2 街・警察署（TEST） | 街で3章耐えたあと、4章目「警察署へ」で入口へ向かい、署内に切り替わる（下記） |
| `sewer` → `subway` | STAGE 3 地下鉄（TEST） | 迷路の下水道（出口を探す）→ 廃駅 → 線路の暗闇（停電）→ 次の駅 → 車両庫（ボス「掘削者」） |
| `lab` | STAGE 4 地下研究所（TEST） | 研究棟入口 → 警報（赤い非常灯）→ 培養槽（停電）→ 発生源（ラスボス「原初体」） |
| `station` | （タイトルには出さない） | 旧STAGE 3。警察署前のプロローグだけの単独ステージ。テスト用に定義だけ残している |

**STAGE 2 の流れ（街 → 警察署）**
1. 街の章：燃える大通り → 封鎖線 → 雨の夜。章の合間に商人。
2. 4章目「警察署へ」（`prologue: true` の章）：群れが押し寄せ、約5秒後に「警察署に入れ！」の指示と光の柱の目印が出る。章の `goal`（入口の位置）と `next`（行き先）で行き先を決める。
3. 入口に着くと暗転し、`enterStage('stationIn')` で署内に切り替わる。所持品と体力は引き継ぐ。
4. 署内の章：ロビー → 停電（照明がほぼ消え、ライトだけ）→ 留置場の暴動（赤い非常灯）→ 地下駐車場（ボス「変異体」）。
5. 署内では肩越しのフラッシュライト（SpotLight）が常に点く。`stationIn.entry = 'city'` なので、クリア後の「もう一度」は街から始まる。
- 街の旧ボス戦（変異体が警察署から出てくる章）は、この流れに置き換えたので今は使っていない。

**STAGE 3 の内容（ユーザー指定・2026-10-31）**
- 最初は下水道。真ん中の下水に**腰までつかって**歩く。**迷路のように入り組んでいて、迷いながら探索する**。
- 水の中から**ワニのゾンビ**が襲ってくる。攻撃の前に**必ず背びれを見せる**。背びれを撃つとひるんで**一定時間浮かぶ**ので、そこを攻撃する。
- 下水道を抜けると地下鉄。**ホームと壊れた地下鉄が捨てられている**（参考画像：アーチ天井、タイルの壁、片側に鉄骨の柱が並ぶホーム）。**壊れた車両の中を通って**探索する。
- 途中で**線路に降りて次の駅**へ、その先の**車両庫**へ向かう。車両庫には車両が**横一列に3〜4両**並んでいる。

**STAGE 3a 下水道（`sewer`・`buildSewer`）**
- 21×21マス（1マス4m）の迷路。`SEWER_MAZE` に固定で書いてある（乱数の種7で作った迷路に、抜け道9か所と3×3の部屋2つを足したもの）。最短ルートは約212m、行き止まり8か所。
- 開始は南のはしご（警察署から降りてきた場所）、出口は北西の角の「METRO」の青い光の扉。
- 水面は高さ0.85m（`STAGE.water`）。水の中は移動が2割遅くなり、足音が水音になり、しぶきが出る。落とし物は水面に浮く。
- 章は1つだけ（`explore: true`）。出口は最初は示さず、150秒たつと光の柱で教える（`hint`）。出口に着くと地下鉄へ切り替わる（所持品・体力は引き継ぐ）。
- 迷路では「直線距離は近いのに道のりは遠い」場所から敵が出ると何分も来ないので、**道のりが45マス以内の出現地点だけ使う**（`navSpawn`）。
- 照明：赤いレンガと暖色のランプ、部屋は赤、出口は青。フラッシュライトが点く。

**ワニのゾンビ（`Croc` クラス、`makeCroc()`）**
- 人型ではないので `Enemy` とは別のクラス。`enemies` 配列に一緒に入る。HP 110、噛みつき22。
- 状態：`lurk`（水中を泳いで近づく。見えない・当たらない・レーダーにも出ない）→ `stalk`（10m以内で背びれを出して近づく。泡と白いしぶき）→ `biteWind`（頭を上げて口を開く。ガードのヒントが出る）→ `bite`（噛みつき）→ `lurk` に戻る。
- **背びれを撃つと**少しダメージを与えて `float`（腹を上にして約4秒浮かぶ）。浮いている間だけ体と頭（2倍）に当たる。手榴弾の爆発でも浮く。噛みつきをガードしても浮く（ジャストなら長め）。
- 当たり判定は `rayHit()`（`raycastWorld()` から呼ぶ）。

**STAGE 3b 地下鉄（`subway`・`buildSubway`）**（北が -z）
- 廃駅（z 14〜42）：西側がホーム、線路に壊れた車両が2両（`walkCar()`、中を歩ける。側面にドア、天井の照明はちらつく）。東側は鉄骨の柱と柵で、その奥にもう1本の線路（入れない）。ホームの北端はがれきでふさがっているので、**車両の中を通らないと先へ進めない**。2両目の先頭は壊れて開いていて、そこから線路のトンネルに降りる。
- 線路のトンネル（z -4〜14）→ 次の駅（z -20〜-4、両側にホーム、階段、「NORTH YARD」）→ 短いトンネル → 車両庫。
- 車両庫（z -43〜-26、ボス戦）：車両4両が横一列（x = -15, -5, 5, 15）。奥に研究所への封じられた扉。
- 章ごとに出現地点（`waves[i].spawns`）と、章の合間に商人が立つ場所（`traderAt`）を変えている：廃駅 → 線路 → 次の駅 → 車両庫と前へ進む流れ。
- 車両の壁は薄いので、敵の通り道の計算で壁を太らせない（`navPad: 0`）。車両の中とドアを敵も通れる。2両の連結部の横はふさいである。
- 新しい敵：作業員ゾンビ（`worker`）。ボス「掘削者 ― THE DIGGER」（`digger`、大槌、HP 2100）。

**STAGE 4 地下研究所（`buildLab`）の配置**
- 開始：車両倉庫の隠し扉からつながるエアロック（z 32〜42）。
- 入口ホール（z 16〜32）：警備デスク、端末、「LEVEL B5」の表示。商人はここ。
- 培養槽の実験室（z -10〜16）：緑の液体が入った培養槽が8基（2基は割れている）。西に標本保管室（檻）、東に制御室（端末・サーバー）。
- 発生源（z -43〜-16、ラスボス戦）：中央に割れた巨大な培養槽と緑の光。
- 新しい敵：研究員ゾンビ（`sci`、白衣）、警備員ゾンビ（`guard`、黒い制服。弾を落としやすい）。ラスボス「原初体 ― THE PROGENITOR」（`origin`、両腕が爪、HP 2600）。

**地下ステージ共通**
- フラッシュライトが常に点く。3章目は停電（`dim`）で、レーダーとキャラクターの見やすさ補正も弱まる（`vis: 0.45`）。
- 壁・天井の材質はステージごとに `SURF.wall` / `SURF.ceil` で差し替える（`clearWorld()` で元に戻る）。
- **ボスは部屋（`STAGE.arena`）から出ない**（`keepInArena()`）。突進で部屋の端にぶつかると壁と同じく気絶する。プレイヤーが部屋の外にいる間は、入口（`STAGE.arenaDoor`）に光の柱の目印を出す。警察署の地下駐車場にも適用した。
- 敵が通れる道は1mの格子で判定し、壁などを0.45m太らせて考える（`navPad` で変えられる）。**通路は幅2m以上の余裕を残すこと**（停めた車両や台車で道がふさがりやすい）。
- 敵の移動まわりの修正（全ステージ共通）：
  - 見通しの判定は体の幅も考える（`pathClear()`）。中心の線だけだと、ドアの枠に引っかかって止まることがあった。
  - 壁際の太らせたマスに入ったとき、壁の向こう側のマスを目指さない（`navDir()`）。
  - 強く吹き飛ばされて1フレームで薄い壁をすり抜けないようにする（`noTunnel()`。0.12m以上の移動だけ調べる）。
  - 壁の角で押し出されたときに壁の反対側へ抜けないよう、`collide(pos, r, prev)` は前のフレームの位置を見て、来た側へ押し戻す（2回くり返して角を解決する）。掴みを振りほどいたときの押し戻しや、プレイヤーと敵の押し合いにも壁判定をかける。
  - プレイヤーが壁に囲まれたマス（角・ドアの脇）に立っていても、まわりの空いたマスから道を探す（`navUpdate()`）。以前は道が見つからず、敵が止まることがあった。
  - 念のため、出現地点へ戻れない場所（マップの外）に出てしまった敵は、出現地点に戻す。

### 5.2 共通の仕組み
- **追跡範囲（ゾーン）**（ユーザー指定・2026-10-31）：プレイヤーがもたもたしているとステージ中の敵が全部集まってきて不快、という指摘を受けて追加。
  - 各ステージを3〜4個の範囲に区切る（`STAGE.zones = [[x0, x1, z0, z1], ...]`。上から順に最初に当てはまったものが、その場所の範囲）。
  - 敵は出現した地点（`home`）の範囲（`zone`）を覚える。**プレイヤーが同じ範囲にいる間だけ追いかける**。範囲から出たら追うのをやめて出現地点へ歩いて戻り（`return`）、そこで待つ（`idle`）。また入ってきたら追う。
  - 例外：すぐ近く（3.5m以内で見えている）の敵は、範囲の境目でも戦い続ける（境目をまたいだとたんに背を向けるのは不自然なため）。
  - 戻り道は、出現地点ごとの距離マップ（`homeField()`、最初に使うときに作る）でたどる。
  - 新しい敵は、プレイヤーがいる範囲の出現地点から出す（16m以上離れた場所、なければ10m以上）。
  - ボスは対象外（ボス部屋から出ないしくみは別にある）。ワニも同じ規則で、範囲外では水中で待ち、背びれを出さない。
  - 範囲の分け方：村・街・下水道は4分割（北西・北東・南西・南東）。警察署内は地下駐車場・西の事務室・東の留置場・ロビー。地下鉄は廃駅・トンネル・次の駅・車両庫。研究所は入口・培養槽の実験室（両翼を含む）・発生源。
  - 注意：範囲の外で待っている敵も、章をクリアするには倒す必要がある（残り数に入る）。

- **章の流れ**：各ステージ4章。最終章はボス戦。章の合間に商人が出て、購入・改造・宝物の売却ができる。Enterで次の章へ進む。
- **死亡**：コンティニューで章の最初からやり直す（章の開始時に所持品を保存している）。
- **武器**
  - ハンドガン「ウォーデン9」
  - ショットガン「ブルドッグ」（2500G）
  - ライフル「ロングアイ」（4500G、スコープ付き）
  - 改造：威力・装弾数・リロード速度を各4段階
- **アイテム**：手榴弾、グリーン／レッドハーブ（調合可）、防弾ベスト。
- **部位ダメージ**：頭は2倍で怯む。脚を撃つとひざをつく。クリティカルで頭が吹き飛ぶ。
- **敵AI**：見通しが良ければ直進し、悪ければ1mグリッドのフローフィールド（BFS）で回り込む。
- **ボスの行動**：薙ぎ払い、叩きつけ（地面に予告円が出る）、突進（SPACEで回避するQTE。壁に激突させるとスタン）、ひざつき（stagger値が一定を超えたとき）。背中の光る核が弱点。
- **音**：効果音とBGMはすべてWebAudioで合成している（素材ファイルなし）。

## 5.4 ムービー（リアルタイム）
- ユーザーが映画のコンテのように**カットごとに言葉で指示**し、それをゲーム内の3D（同じPS1風の描画）で組む。録画した動画ではない。
- 仕組み（`game.js` の Cutscenes 区画）：
  - 専用のシーン `cineScene` とカメラ `cineCam`。`game.state = 'cine'` の間はこちらを描く。
  - ムービーは `MOVIES` に1本ずつ書く。`dur`（長さ）、`subs`（字幕：[開始秒, 終了秒, 話す人, セリフ]）、`fade(t)`（暗転の濃さ）、`sound(t)`（ヘリの音：外 `out`／中 `in`）、`render(t)`（その時刻の絵を作る）。
  - **すべてムービー内の時刻 t から計算する**（前のフレームに頼らない）ので、好きな時刻へ飛べる。テストはこれで静止画を撮る。
  - 上下の黒帯、字幕（話す人の名前は金色）、「スキップ ▶」ボタン。Enter・Space・Esc でもスキップできる。
  - キャラクターは `makeHumanoid` の人形をポーズ（`applyPose`）で動かす。口や表情はないので、話している人は首を小さく揺らす（`talk()`）。座り姿勢は `SEAT()`。
  - `playMovie(id, 終わったら呼ぶ関数)`。STAGE 1 はタイトルでカードを押すとムービー → ゲーム開始。
- **STAGE 1 スタートムービー（`MOVIES.stage1`、45秒、カット6まで）**
  - カット1（0〜7秒）：雲と霧の中、ヘリの羽音。約2秒は雲だけ。雲の中からヘリの正面が近づき、4〜6秒あたりは風で揺れるヘリを正面からしっかり映す。最後の1秒でヘリがカメラの上を越えて後ろへ飛び去り、カメラはそれをパンで追いかける。暗転。
  - カット2（7〜14秒）：明転。キャビンを後ろから。主人公は**左側面のロングシートに横向きに座り**、資料を読み、やがて膝に置いて考えごとをする。コックピットでは副操縦士がボタンやレーダーを確かめる。副操縦士「自動運転、解除します。ここからは手動で目的地まで向かいます。」うなずく操縦士。
  - カット3（14〜25秒）：キャビン側からコックピットへズーム（最初の4秒）。操縦士「にしても、今回の任務は不気味ですよね。カーヴァーさんも、あんまり気乗りしないでしょう。」（主人公の方を振り返る）副操縦士「いわゆる貧乏くじってやつですね。」「カーヴァーさんも出世街道を渡っているから、上からの指令は無下にはできませんよね。」（主人公の方を振り返る）。話しかけられている間、主人公はコックピットの方へ軽く顔を向ける。
  - カット4（25〜31秒）：コックピットから、操縦士2人と主人公の方を向く。副操縦士は頭上のスイッチ、操縦士は下の計器を触って確かめる（約2.5秒）。操縦士「ただ、今回の任務は前任者が失踪したとかで、奇妙さでいったら折り紙付きです。」主人公は左手に地図を持って見ている。
  - カット5：コンテに無かった（ユーザーの番号どおり、次は「カット6」）。
  - カット6（31〜45秒）：カット4のカメラ位置から、カーヴァーが左手に持つ地図へズーム（約3秒）。手先と、赤丸で印をつけた村が映る。じっと見る。操縦士「そこの村、たった一晩で住民全員が消えてしまったそうです。」「第一発見者が言うには、消える直前、彼らの目が赤いとか、燃えてるとかなんとか…」「錯乱状態にあったので、どこまで信じていいのか分かりませんが。」副操縦士「もちろんカーヴァーさんは戻ってくると信じてますから。」
  - 地図は `cine.map`。左手の位置に置き、主人公の目とカメラの間の方向を向ける（毎フレーム計算）。山・川・道・森と、赤丸で囲んだ村を手描き風に描いている。
  - **長さを延ばしたカット**：カット4は指示5秒→6秒、カット6は指示8秒→14秒（セリフを字幕で読める長さにするため。長い2つ目のセリフは2枚の字幕に分けた）。
  - **ヘリの音**：外のカットでは、カメラとヘリの距離で音量とこもり具合が変わる（遠いと小さくこもった音、真上を通るときが最大）。左右の位置にも合わせる（`MOVIES.stage1.level()`、`heliLevel()`）。機内は一定の、こもった音。
  - **機内の振動**：カット2・3のカメラは不規則に小さく揺れる（細かい振動と、ときどきの小さな揺れ。`cabinShake()`）。酔わないよう、ごく小さくしている。
  - **カット3の長さ**：指示は4秒だったが、セリフ3つを字幕で読める長さにするため11秒にした（ズーム自体は4秒）。
  - 主人公の名前はセリフでは「カーヴァーさん」（レイ・カーヴァー）。操縦士は右の席、副操縦士は左の席。
  - 続きのカットはまだない。今はカット6のあと暗転してゲームが始まる。

## 7. 既知の課題・今後の候補

- **難易度**：蹴り（大ダメージ源）をなくしたので、弾の消費が増えた可能性がある。必要なら弾のドロップ率を上げる。ジャストガードの受付時間（0.2秒）も要調整。
- **協力プレイ**：提案だけ済み（未着手）。おすすめは「ブラウザどうしを直接つなぐ方式（PeerJS、ホスト側で計算）」。ダウンと復活、各自の所持品、2人とも準備完了で次の章へ、などのルールも提案済み。
- **固定カメラ**：初代バイオ風の固定カメラ（警察署だけ、など）は未着手。操作が根本から変わるため、やる場合は要相談。
- **ムービー**：STAGE 1 のスタートムービーはカット6まで（カット5は欠番）。続きのコンテ待ち。
- **物語の演出**：会話シーンや手記、ステージをまたぐ一本道の流れなどは未実装。5.0 の大枠に沿って、TEST版のステージを確認したあとで組み立てる。
- STAGE 3・4 は TEST 版。ワニの背びれは10m先だと小さめなので、見えにくければ大きくする。敵の数・ボスの強さ・配置はまだ調整していない。
- 街・警察署の商人の位置が、敵の通れる道の外にある（`positions.js` で `trader dist=-1`。以前からある。実害は未確認）。
- タイトルのステージカードは4枚。PCは横一列、スマホ縦は2×2、スマホ横は横一列（説明文を隠す）。
- 自動テスト（`inrun.js`・`boss.js`）の自動操作は、待っている敵しか残っていないとき、その敵の出現地点へ瞬間移動する（範囲のしくみに合わせたもの）。到達テスト（`reach*.js`）は道がつながっているかを見るため、範囲を無効にして実行する。
- `tools/test/inrun.js` は、自動操作が敵を倒しきれずにまれに TIMEOUT になることがある（ゲームの不具合ではない。もう一度実行すると WIN になる）。
- 実機のスマホと実GPUでの動作確認は、ユーザーに依頼している（開発環境ではGPUなしのSwiftShaderで確認している）。

## 9. テスト方法

開発環境には Chromium と Playwright が入っている（`require('playwright')` がそのまま使える）。GPUがないので、`--use-angle=swiftshader` で起動する。描画は遅い（1280×720で約1fps）ので、ゲームの進行は `__game.sim()` で早送りする。

```bash
cd <リポジトリ>
python3 -m http.server 8766 &        # テストスクリプトは 8766 番ポートを前提にしている
node tools/test/boss.js /tmp/out     # 街のボス戦を無敵状態で最後まで（状態遷移とクリア画面）
node tools/test/inrun.js /tmp/out [stage]  # 全4章＋ボスを通しで（stage 省略時は stationIn。subway / lab も可。ボス章ではボス部屋の入口へ移動する）

node tools/test/movie.js /tmp/out [movie]  # ムービーの静止画（決めた時刻ごと）＋最後まで流れるか・スキップできるか
node tools/test/zones.js             # 追跡範囲：範囲外では待つ／入ると追う／出ると戻る、新しい敵はプレイヤーの範囲に出る、ワニも範囲外では浮上しない
node tools/test/croc.js /tmp/out     # ワニ：背びれを見せる → 撃つと浮かぶ → 浮いている間に倒せる／撃たないと噛みつく
node tools/test/tour.js /tmp/out [stage,...]  # 下水道・地下鉄・研究所の各エリアを撮影
node tools/test/guard.js             # ガード（ジャスト／通常／なし／背後／掴み／長押し／移動速度）
node tools/test/positions.js         # 全ステージ（村・街・警察署前・署内・地下鉄・研究所）の出現地点・開始位置・商人・ボス位置が壁の中にないか
node tools/test/reach.js             # 村・街で、全出現地点の敵がプレイヤーにたどり着けるか

node tools/test/trade_touch.js /tmp/out  # スマホ縦・横で「商人と取引」ボタンが出て、タップで店が開き、閉じられるか

node tools/test/visibility.js /tmp/out [名前]  # 各ステージ・各章で主人公と近・中・遠の敵の見え方を撮影（変更前後の比較用）
```

5. STAGE 3 地下鉄（仮）・STAGE 4 地下研究所をTEST版で追加。STAGE 2 を街→警察署の一続きに。ボスが部屋から出ないように
